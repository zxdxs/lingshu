# 104 參考傷寒站：把靈樞做成同樣形狀的離線閱讀器

參考的是同一台電腦上的 `~/Desktop/shanghan`（桂林古本《傷寒雜病論》讀書訓練站），**只借架構與檢查方法，不搬內容、不搬程式碼**。

**引號規矩同前**：「」只給《靈樞》原文，經機器驗證；『』給其他典籍、注家與我自撰的詞。

---

## 一、傷寒站值得借的五件事

| 它怎麼做 | 我們怎麼用 |
|---|---|
| **純靜態、零依賴、file:// 可開**（index.html＋assets/app.js＋data.js＋style.css） | 同樣四件套：`reader/index.html`、`app.js`、`data.js`、`style.css` |
| **資料先產生成 `window.SH`**，前端只渲染 | `scripts/build_reader.py` 生成 `window.LS`（374 KB） |
| **hash 路由 + 視圖註冊表**（`VIEWS.xxx`） | 同一個模式，八個視圖 |
| **localStorage 記進度**（已讀、作答） | 已讀 81 篇、作答對錯紀錄 |
| **首訪確認閘 + 常駐限制條 + 頁腳四連結** | 同樣三件，閘上寫『不可據以施治』 |
| **`site_check.js` 用 DOM 樁跑每個視圖，掃 undefined／空區塊** | `scripts/check_reader.js`：八個視圖全跑，節點數與 HTML 長度都印出來 |

〔歸〕最值得學的是**最後一條**：它把『每一頁都渲染過一遍』變成可執行的檢查，而不是靠人逐頁看。我們照做了，第一次跑就抓到 `Option` 未定義與 `STATE` 先用後宣告兩個錯——那兩個錯在瀏覽器裡就是空白頁。

---

## 二、不借的三件事

1. **方證／劑量／六經框架**——靈樞沒有方，硬套會得到假的傷寒論。
2. **條文號的權威感**——我們的篇序是自建，若做句 ID 必須註明『非古本原有』。
3. **它的資料與文字**——一句都沒搬。

## 四、這一輪做出來的

```
reader/
├── index.html           外殼（header／nav／main／footer）
├── assets/
│   ├── data.js          374 KB，由 build_reader.py 生成（81 篇原文＋1031 題＋834 索引＋34 限制＋14 矛盾）
│   ├── app.js           八個視圖：理念／通讀／題庫／索引／概念圖／限制／我的／關於
│   └── style.css        紙色、宋體、單欄 920px
└── （_preview_*.html 為截圖用，已 gitignore）
```

驗證：

```
node scripts/check_reader.js
  ✓ idea ✓ read ✓ items ✓ index ✓ concept ✓ limits ✓ mine ✓ about
```

八個視圖都有內容、無 undefined／NaN／空區塊。

截圖：`export/reader_通讀.png`（81 篇列表）、`export/reader_題庫.png`（題卡與篩選）。**我看不到截圖**（視覺 API 429），只能確認尺寸與節點數，請你過目。

## 五、和傷寒站相比，還缺什麼

1. **準備性知識**：音釋層、度量換算、九鍼名稱——初學者卡住的地方，還沒有頁面。
2. **記誦／抽背**：靈樞可背的句子（如「上工治未病」「用鍼之類，在於調氣」）沒有做成模組。
3. **掌握度**：現在只記對錯總數，沒有按篇／按題型的正確率。
4. **互動圖譜**：概念圖只是 12 張 PNG，不能點節點。
5. **句級 ID**：傷寒有條文號，我們仍只能指到篇（`docs/103` 已提出）。
6. **授權與聯絡**：頁面上是「待定」「待補」。

---

## 六、一句話

傷寒站給的是一個**已經跑通的發布形狀**：四件套、八到十三個視圖、離線、進度存本機、每個視圖都被機械檢查過。我們把形狀搬過來，內容仍然是靈樞自己的——**這一輪最大的收穫不是頁面，是那支會替你看每一頁的檢查腳本。**
