# 105 閱讀器升級：從八頁骨架到十個視圖

`docs/104` 的閱讀器被指出「太簡陋」。這一輪照著傷寒站的完成度補：版面、模組、狀態、檢查。
**引號規矩同前**：「」只給《靈樞》原文，經機器驗證；『』給其他典籍、注家與我自撰的詞。

---

## 一、哪裡簡陋

| 問題 | 具體 |
|---|---|
| 版面 | 只有單欄＋細線，沒有層級、沒有留白節奏、沒有首頁 |
| 模組 | 八個視圖，其中「準備」「方法」完全缺席；概念只有 12 張圖的連結 |
| 狀態 | 只記『已讀／作答』，沒有進度條、沒有正確率 |
| 題目 | 全部填空式（顯示答案、自己按對錯），選擇題的選項沒用上 |
| 資料 | 概念、校勘、九鍼、音釋都沒進前端 |

---

## 二、這一輪改了什麼

### （1）版面：一套設計系統

- 色：紙 `#f6f1e6`、卡 `#fffdf7`、墨 `#221f1a`、朱 `#8f3b2b`、赭 `#b0714f`、青 `#3f6b57`。
- 字：介面無襯線；原文襯線、行高 2.0、首行縮排。
- 元件：hero、stat 卡、pill、進度條、可折疊卡、表、按鈕（實心／ghost）。
- 響應式：手機上統計卡改兩欄、hero 縮小、印章隱藏。

### （2）首頁：先給規模與可信度

hero（書名、一句話、四顆數字：81 篇／65,085 字／1031 題／834 索引）＋三個入口（讀／練／查）＋『這一版你能信到什麼程度』（引文 804 段、答案分型、模組 264 條、限制 34、矛盾 14）。

### （3）十個視圖

| 視圖 | 這輪新增 |
|---|---|
| 首頁 | 全新 |
| 通讀 | 搜尋＋按卷篩；全書已讀進度條；篇內顯示校記與該卷音釋 |
| 題庫 | 進度與正確率；選擇題可點選（選項亂序、即時判對錯）；案例題標記 |
| 概念 | 12 個概念卡：摺疊展開後是『層／原文／出處』表，附圖連結 |
| 索引 | 關鍵字＋類別雙篩 |
| **準備** | 九鍼九條（名、長、用途）＋十二卷音釋節錄 |
| **方法** | 校勘 19 點表（底本／他本／判定）＋矛盾 14 條表 |
| 限制 | 34 條表＋三項最要緊 |
| 我的 | 通讀進度、題庫進度、三種題型的正確率、清除 |
| 關於 | 底本、規模、驗證、答案分型、授權待定、引用格式 |

### （4）資料層

`build_reader.py` 多帶四類資料：概念（12）、校勘（19）、九鍼（9）、音釋（12 卷）＋每篇題數。前端不再有寫死的清單。

## 五、一句話

「簡陋」不是因為頁面少，是因為**每一頁只做了一件事**。這一輪讓每一頁都同時給狀態、給操作、給依據——版面變重了，但讀者不必再猜自己該做什麼。
