# 113 發布待決：把只有你能決定的事收成一份檔

前 112 份文件把內容、稽核、閱讀器都推到可以給人看的狀態，但發布前卡在幾個
非技術問題上：**授權、聯絡、案例題比例**。之前這些字樣散在 `app.js`、`make_proof.py`、
README 各自硬寫，改一處就會漏另一處——正是本站反覆吃過的同一事實多份副本的虧。

這一輪把它們收成單一來源，並讓回歸檢查會把「還沒定」當成可量測的缺口。

---

## 1. 單一來源：`data/發布資訊.json`

| 欄位 | 現值 | 誰會讀 |
|---|---|---|
| `站名` | 中醫典籍導讀﹣靈樞經 | 閱讀器標題／關於頁、大樣稿封面與封底、`meta.title` |
| `英文名` | 空 | 空則對外只用中文名（可留空） |
| `副標` | 原文 · 註 · 圖 · 題 · 卡 | 大樣稿封面 |
| `版本` | 1.0.0 | 大樣稿封面、打包 manifest |
| `授權` | **CC BY-NC-SA 4.0**（已定案） | 關於頁、封面、manifest；決定後才把 `LICENSE.txt` 包進 zip |
| `聯絡` | **待補** | 關於頁、封底 |
| `案例題` | 維持 6 道樣板（已定案） | 封底『已定案』一格 |
| `Anki實機` | **未測** | `check_all`／封底；驗過後改成「已測（版本、708 卡）」 |
| `引用格式` | 站名＋版本＋授權＋篇序篇名 | 關於頁 |
| `必要` | `["授權","聯絡","Anki實機"]` | `check_all` 的`發布待決`與打包的 LICENSE 判斷 |

`選項`／`待決說明` 只給人看，不進頁面。

## 2. 三個消費端（都改成讀同一個檔）

- `scripts/build_reader.py` → `LS.meta.release`，並補上 `ans_yuanwen/tuisuan/zhengli`
  三個計數（原本`原文 669／推算 24／整理語 15`是寫死在 `app.js` 的字串，題庫一改就過期）。
- `reader/assets/app.js` 的「關於」頁 → 授權／聯絡未定時**一定**顯示`待定／待補`，
  並列出「待決：…」；不再有假裝已定的可能。
- `scripts/make_proof.py` → 封面授權欄與封底待決事項頁；封底只留**真正還沒定的**
  （聯絡、Anki 實機），其餘進『已定案』一格，不再列一堆假選項。
- `scripts/package_release.py` → manifest 增列 `站名`／`授權`／`聯絡`／`發布待決`；
  `LICENSE.txt` 的收錄條件是**授權已定且檔案存在**（與聯絡無關），
  但仍有必要欄位未決時印出「⚠ 尚未定案…（僅可作審閱稿）」。

## 3. 讓「未定」跑得進回歸

`check_all.py` 新增指標 `發布待決`（讀 `必要` 清單，數值為仍未決的欄位數）。
現況 = **2**（聯絡、Anki 實機未測）——不是 0，這是實話，也因此在每次 `check_all` 都會被看見。

`check_reader.js` 新增 release 段：比對 `data.js` 的 `meta.release` 與
`data/發布資訊.json` 逐欄是否一致，並檢查關於頁確實出現站名、已定的授權字串、
未定的`待補`與「Anki 實機」字樣。

負向測試（確認檢查真的會紅）：
把 `data.js` 的授權改成 `CC BY-SA 4.0` 而檔案不動 → `✗ release data.js 與
data/發布資訊.json 不同步：授權；授權未定卻未顯示「待定」`，`node` 退出碼 1；
還原後退出碼 0。

## 4. 順手修掉的假陽性

`check_all` 的`文件引文待核`一直是 1，來源是 README 一句『編者歸納』被
`「」` 包住，而依本站規則 `「」` 只給靈樞原文、自訂術語要用 `『』`。
改成 `『編者歸納』` 後指標歸 0——不是把檢查放寬，是把寫法改對。

## 5. 已定案與仍待你決定的

已定案（2026 審閱）：
- **授權 CC BY-NC-SA 4.0**。根目錄 `LICENSE.txt` 為通知文件：說明原文屬公共領域、
  本計畫新增的標點／校記／題目／圖表依 CC BY-NC-SA 4.0 釋出，法律文本指向
  creativecommons.org 的 canonical 版本（我不代擬法律條文）。
- **案例題維持 6 道樣板**，等實際有人用過再決定是否量產。

仍待你：
1. **聯絡**：一個可公開的去識別化信箱或表單網址；填入 `聯絡` 後重建即可。
2. **Anki 實機匯入**：`export/靈樞_填空.apkg`（708 卡）我這端只驗了檔案結構，
   沒有真的匯入 Anki；驗過後把 `Anki實機` 改為「已測（Anki 版本、708 卡）」。

兩項都填妥後，`check_all` 的`發布待決`才會是 0，那時才可以發布。

## 6. 重跑順序

```bash
python3 scripts/build_reader.py      # 站名／授權／聯絡進 data.js
node    scripts/check_reader.js      # 關於頁與單一來源一致性
python3 scripts/make_proof.py        # 大樣稿封面與封底
python3 scripts/check_all.py --write # 基準（含`發布待決`）
python3 scripts/check_all.py         # 應為 差異 0
python3 scripts/package_release.py 1.0.0
```

改 `data/發布資訊.json` 後**一定要重跑 `build_reader.py`**，否則 `check_reader`
會用「不同步」把它擋下來——這是刻意的。
