# 115 聯繫頁：照傷寒站的骨架，但每一項數字都由本站資料算出來

你要的是『聯繫頁同傷寒站』。傷寒站的 `<聯絡>` 頁骨架是四段：
**引言 → 最需要人幫忙的事 → 怎麼聯絡 → 相關站點 → 結語＋一句警語**。
我照這個骨架做，但內容不抄——五項求助全部由脚本從本站資料算出，避免『寫在頁上的數字跟站上對不上』。

## 1. 資料怎麼來

新增 `scripts/build_contact.py` → `data/聯絡.json` → `build_reader.py` 塞進 `LS.contact`。
頁面不手寫任何數字：

| 求助項 | 數字怎麼算 |
|---|---|
| ① 句ID 與原文的對應（最需要） | 題庫 `句` 欄為空者 91／1031；校勘點 `句ID` 為空者 6／19 |
| ② 待專家核的判斷 | 填空答案類型『整理語』15 條；案例題 6 道（`-CASE-`）；註家配對 19 條 |
| ③ 主題與概念的分類 | `主題.json` 5 個主題；`data/多層_*.json` 12 張概念卡 |
| ④ 太素對校的空白 | `三源覆蓋率.json` 判讀：66 篇可對校、15 篇半可對 |
| ⑤ Anki 實機驗證 | `發布資訊.json` 的 `Anki實機` 仍為『未測』 |

⑤ 跟其他四項不同：它不是『內容有洞』，是『有一件事沒人按過』。放在同一頁，是因為
回報者不需要知道我們的內部分類，他只需要知道『這裡有事可以做』。

## 2. 頁面行為

- 入口：頁腳常駐 **✉️ 指正與聯絡**（仿傷寒站做法，不佔主導覽）；關於頁多一行連結。
- 郵箱：讀 `data/發布資訊.json` 的 `聯絡`。**未填就顯示『待補』**，不靜靜留白——
  這是本站對待不確定的一貫做法，聯絡方式也不例外。
- 相關站點：傷寒站（`solve-lab.cn`）、聲韻站（`shenglv.org.cn`），外部連結一律
  `target="_blank" rel="noopener noreferrer"`。
- 結語下方照傷寒站右下角放警語——這裡用 `安全提醒短`，與全站同一句話。

## 3. 順手抓到一個更嚴重的問題

做這一頁時要 dump 渲染結果核對文字，發現 `card`、`small` 這些字**原樣出現在輸出裡**。
追下去：`app.js` 的輔助函式是

```js
function h(tag, html, cls)   // 第二個參數是內容，第三個才是 class
```

但全檔有 **30 處**寫成 `h('div', 'card', '')`、`h('div', 'grid')`、`h('div', 'hero', '')`：
第二個參數被當成 class，第三個是空字串 → **class 全部落空**，內容則先被塞進一個
`card`/`grid` 字樣、再被隨後的 `innerHTML` 覆蓋掉，所以畫面『看起來有東西』，只是沒有樣式。

也就是說：`.hero` 的漸層、`.card` 的邊框圓角、`.grid` 的多欄、`.orig` 的宋體字級與行高、
`.row` 的按鈕橫排、`.tiao` 的分隔線，**在我做完『以主題重排』那幾輪裡一直是失效的**。
這解釋了為什麼站看起來總比設計稿單薄——不是設計不夠，是 class 沒掛上。

修正：30 處全改為 `(tag, '', cls)` 的順序（含 `h('p','small','')` → `h('p','','small')`）。

### 為什麼之前沒抓到

`check_reader.js` 只掃內文（`undefined`／`NaN`／空視圖），**從沒檢查過節點上掛了什麼 class**。
文字齊全、節點數正常，測試就綠了。這是『檢查了內容，沒檢查外觀』的典型盲點。

### 新的守門

`check_reader.js` 新增 classes 段，逐視圖點名必要類別：

| 路由 | 必須出現 |
|---|---|
| `#/home` | `hero` `card` `grid` `alert` |
| `#/read`（篇目列表） | `list` `tiao` |
| `#/read?seq=40` | `orig` |
| `#/items?seq=40` | `card` |
| `#/limits` | `alert` |
| `#/contact` | `card` `want-k` `site` `contact-row` |

負向測試：把 `h('div','','hero')` 改回 `h('div','hero','')` → `✗ classes /home 缺 .hero`，退出碼 1；
還原後全過。這樣同一個錯不會再無聲無息。

順帶也修了 `h('div','gate')`：首次確認頁的紅框與留白樣式之前同樣沒生效。

## 4. 新增的檢查

`check_reader.js` contact 段：

- 求助項少於 3 項 → 紅；
- `聯絡.json` 的每個 `want.k`、每個 `sites.url` 都必須出現在頁面；
- 頁尾必須有 `seal`（即安全提醒短句）；
- 郵箱狀態與 `contact_ready` 一致：已填→必須看得到地址且不得出現『待補』；
  未填→必須看得到『待補』。
