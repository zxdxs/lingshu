# 116 把站放出來跑一遍：真瀏覽器冒煙測試

你要『把首頁放出來，跑一遍看看』。這一輪做三件事：起本機伺服器、用**真的 Chrome** 跑一遍
（不是自製 DOM 樁）、把這次跑出來的東西變成可以重複執行的檢查。

## 1. 怎麼開

```bash
cd reader && python3 -m http.server 8080 --bind 127.0.0.1
# 瀏覽器開 http://127.0.0.1:8080/
```

也可以直接雙擊 `reader/index.html`（`file://` 一樣能跑，本專案零依賴、零外部請求）。
本輪已在 `127.0.0.1:8080` 起一個背景服務，實測四個資源都 200：

| 資源 | 狀態 | 大小 |
|---|---|---|
| `/` | 200 text/html | 1.7 KB |
| `assets/app.js` | 200 text/javascript | 37.7 KB |
| `assets/data.js` | 200 text/javascript | 751.8 KB |
| `assets/style.css` | 200 text/css | 9.4 KB |

補了一個 inline SVG favicon（`data:` URI，不新增檔案、不發外部請求），免得每次開啟都在
server log 留下一行 404。

## 2. 用真 Chrome 跑：`scripts/smoke_browser.py`

`check_reader.js` 用的是自製 DOM 樁，能抓 `undefined`、缺節點、缺 class，但抓不到
『樣式沒生效』『事件綁錯』『localStorage 沒寫進去』——那些只有真瀏覽器會現形。
所以新增一支：把 Chrome 當使用者用，真的載入、真的點按鈕、真的切路由。

做法：暫存一份頁面，在 `data.js` 之前注入一段計時腳本，跑完把結果寫進隱藏 `div` 的
`SMOKE={...}`，再用 `--headless=new --dump-dom` 取回解析。三個關鍵細節：

- `--no-sandbox`：本機沙箱下 Chrome 起不來（`sandbox initialization failed`），這支只跑本機檔案；
- `--user-data-dir`：每次給一個乾淨 profile，避免 `localStorage` 殘留讓「未同意」情境失真；
- `--virtual-time-budget`：等路由與 `setTimeout` 跑完再 dump，否則只能拿到骨架。

## 3. 跑出來的結果（本輪；路由數後來隨 docs/119 減為 15）

16 條路由 + 2 個情境，全部通過：

```
✓ home          h1=靈樞經        card=9   alert=1
✓ themes        h1=靈樞在講什麼     card=6
✓ read          h1=通讀
✓ read?seq=40   h1=陰陽清濁
✓ items         h1=題庫          card=21
✓ items?seq=40  h1=題庫          card=14
✓ concept       h1=概念          card=12
✓ index         h1=索引
✓ coverage      h1=覆蓋表
✓ prep          h1=準備
✓ method        h1=方法與校勘
✓ collation     h1=校勘：三源並排
✓ limits        h1=已知限制        alert=1
✓ mine          h1=我的
✓ about         h1=關於
✓ contact       h1=指正與聯絡       card=5
✓ gate          未同意時停在確認頁，且看得到安全提醒
✓ interact      顯示答案／答對／選項判定／切路由都動作（紀錄 2 筆）
```

`interact` 那一項是真的在瀏覽器裡做的四步：

1. 找到『顯示答案』按下 → `.ans` 由 `display:none` 變可見，內容 52 字（含「亦可」與出處）；
2. 按「答對」→ 按鈕文字變『答對 ✓』，`localStorage` 的 `log` 多一筆；
3. 點一個選項 → 該按鈕被標 `right`/`wrong` 並 `disabled`；
4. 把 hash 改成 `#/limits` → 300ms 後 `h1` 變『已知限制』且紅框在，`window.onerror` 全程為空。

每條路由同時驗：`h1` 非空、頂欄等於安全提醒短句、導覽 13 項／頁腳 5 項、必要元素數達標。

## 4. 這支與其他檢查的分工

| 檢查 | 粒度 | 抓什麼 | 抓不到什麼 |
|---|---|---|---|
| `check_all.py` | 資料 | 計數、引文、答案分型、發布待決、安全提醒缺漏 | 前端一切 |
| `check_reader.js` | DOM 樁 | 每視圖 undefined／空視圖／必要 class／單一來源一致 | 真 CSS、真事件、真 localStorage |
| `smoke_browser.py` | 真 Chrome | 上面的全部＋版面元素真的存在、按鈕真的動作 | 畫面好不好看（仍需人眼） |

三支互補，不是三份重複。

## 5. 一句實話

冒煙測試證明的是『網頁沒有壞』，不是『內容可教』。後者只有你與帶教醫師能判斷。
畫面我也**沒有辦法替你看**——這台環境的影像辨識額度不足（HTTP 429），
`export/reader_gate.png`、`export/reader_home_1280.png` 是我拍的，但只能保證它非空、
尺寸合理（1280×948 的確認頁、1280×2466 的首頁），好不好看得你自己開來看。
