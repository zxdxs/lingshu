# 119 刪掉拼湊：索引、覆蓋表、音釋截斷

你要『刪除網站上價值不高的拼湊內容』。我先訂一個判斷標準，再照標準刪，免得憑喜好。

**標準**：一頁如果存在的理由是『這份資料已經有了』，而不是『讀者需要它』，就是拼湊。
用這個標準連 `LS` 裡的資料一起清，而不只是把導覽上的字拿掉——藏起來的頁仍然會出現（舊連結、搜尋引擎、書籤）。

---

## 一、刪掉的

### ① `#/index` 索引（834 條，整個視圖）

內容是『名詞 → 篇 → 位置』，位置欄是字元位移（例如 `566`、`667`）。
對讀者而言那不是位置，是雜訊；也沒有定義、沒有語境，同一名詞出現幾次就列幾列。
查名詞的需求本來就由兩處承擔：通讀頁搜篇名、題庫頁篩題型與篇。

處置：視圖、`NAV` 項目、`LS.index`（834 筆）一併移除。
`export/索引.csv` 仍留在打包裡——想查的人直接開 CSV，站上不做半成品。

### ② `#/coverage` 覆蓋表（整個視圖）

兩塊內容，各自都有問題：

- **三源覆蓋率**（太素／類經 K4／K12 重合率、81 篇逐列）：這是**專案內部的品管指標**，
  用來判斷某篇能不能對校。它回答的是『我們的工作做到哪』，不是『讀者該讀什麼』。
- **81 篇進度表**（字數／題數／已讀／正確率）：與通讀頁清單重複，
  而「正確率」在「我的」頁已經按題型算過。

處置：視圖、`NAV` 項目、`LS.coverage` 移除；`data/三源覆蓋率.json` 留在打包裡（方法頁有連結說明）。

### ③ 「準備」頁裡的音釋（12 卷 × 前 220 字）

`.slice(0, 220)` 是抽取時留下的長度上限，結果每卷都是這種東西：

> 宛陳(藴又於阮切/上音鬱又音)氂(又音毫/莫高切)在腧(切/春遇)鑱(切/鉏銜)…

反切與正文交錯、被硬切在句中。這不是內容，是**抽取過程的殘渣**——而且頁面開頭還寫著
『先補三樣：九鍼、音釋、度量』，實際只渲染兩樣，度量根本沒做。承諾與內容不符，就是拼湊的定義。

處置：整段移除，`LS.yinshi` 也不再進前端資料（`底本/音釋層.json` 保留供溯源）。

## 二、順手把「準備」改成真的能用的「九鍼」

拿掉音釋後，這頁只剩九鍼表。與其留一個「準備」的空殼，不如把唯一有價值的部分做實：

- 導覽改為 **九鍼**；
- 表格每列加上該鍼的**原文**（`原文：一曰鑱鍼，長一寸六分`），出處是〈九鍼十二原〉與〈九鍼論〉；
- 補一句兩篇毫鍼長度不同（一寸六分／三寸六分）是底本自身差異，不是排印錯；
- 底部給三個回原文的連結（〈九鍼十二原〉、〈九鍼論〉、〈官鍼〉）。

## 三、沒刪、但想過要刪的

**首頁的『訓練怎麼進行』與『驗收四層』**：兩張表是從解題站借來的框架，確實有拼湊味。
但『應知→填空（答案類型：原文）／應會→選擇與辨誤／理解→概念卡／遷移→案例題』這個對應
是真的落到本站題型上，不是空話，所以留著。**你若覺得多餘，說一聲就刪**——這一頁沒有它的資料來源，
刪起來比索引乾淨。

**概念（12 卡）、主題（5 個）、校勘（19 點）、限制（34 條）**：都是站的核心，不動。

## 四、刪完之後要防的兩件事

刪頁面最容易留下的是**死連結**。所以加了兩道：

1. `check_reader.js` 新增 removed 段：`window.__ROUTES` 裡若再出現 `index`／`coverage` 就紅。
2. `smoke_browser.py` 新增 links 段：掃每一頁的 `a[href^="#/"]`，每個目標都必須是存在的視圖。

第二道立刻抓到一個陳年死連結：頁首品牌標誌 `href="#/idea"`——`idea` 這個視圖早就不存在，
因為路由有『找不到就回首頁』的 fallback，所以按下去『看起來正常』，實際上一直在偷偷回首頁。
現已改為 `#/home`。**這就是『靜默 fallback 掩蓋壞連結』的典型**，以後掃得到。

## 六、重跑與檢查

```bash
python3 scripts/build_reader.py
node    scripts/check_reader.js     # 含 removed 段
python3 scripts/smoke_browser.py    # 含 links 段（死連結）
python3 scripts/check_all.py --write && python3 scripts/check_all.py
```

一句話：**刪掉的不是『不好看的頁』，是『沒有讀者的頁』**。資料還在打包裡，站上只留有人要看的。
