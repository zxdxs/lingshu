# 127 先整理：導覽、死路、地圖

你說『先整理，再做專題』。這一輪沒有新增內容，只做四件事：**導覽分組、消滅死路、首頁地圖、把數字對齊**。

## 1. 導覽：15 個平列項 → 六組

原本 15 個項目一路平列，讀者看不出『先讀哪、後查哪』。現在按用途分六組，用細分隔線隔開：

| 組 | 項目 |
|---|---|
| 入門 | 首頁 · 主題 · 通則 |
| 讀原文 | 通讀 · 十二經 · 病候 |
| 練與查 | 題庫 · 概念 |
| 對照 | 異同 · 九鍼 |
| 查核 | 方法 · 校勘 · 限制 |
| 自己 | 我的 · 關於 |

排序依據不是建立時間，是**閱讀順序**：先知道靈樞在講什麼（主題、通則），再讀原文，再練，最後看它可不可信。
分隔線用 `<span class="nav-sep">`，不是連結，所以連結數仍是 15（冒煙測試照舊驗）。

## 2. 死路：九個頁面走到底就沒路了

用程式掃每個視圖的出站連結，發現 **9 個頁面沒有任何站內連結**：通讀、題庫、概念、九鍼、方法、校勘、限制、我的、聯絡。
讀者從導覽進去，讀完只能按瀏覽器上一頁——這是導覽設計的問題，不是內容的問題。

補了一致的「接著看」列（`nextLinks()`），每頁三個去處，依該頁的下一步安排：

- 通讀 → 通則／十二經／練這一篇的題
- 題庫 → 我的（成績）／通則（原則）／限制（哪些題待核）
- 概念 → 通則／十二經／練概念題
- 九鍼 → 十二經／校勘（毫鍼長度差異）／方法
- 方法 → 校勘／限制／異同
- 校勘 → 限制／方法／回原文
- 限制 → 方法／聯絡／我的
- 我的 → 通讀／題庫／限制
- 聯絡 → 限制／關於／首頁地圖

掃描結果：**dead ends = 0**。

## 3. 首頁：拿掉三張「立場卡」，換成全站地圖

原本首頁有三張卡（目的／價值／為什麼現在做），是借來的敘事框架，資訊量低且與導覽重複。
換成**六組全站地圖**，每一項附一句說明：

```
入門    主題 / 通則
讀原文  通讀 / 十二經 / 病候
練與查  題庫 / 概念 / 九鍼
對照    異同
查核    方法 / 校勘 / 限制
自己    我的 / 關於 / 聯絡
```

15 個頁面全部在地圖上，讀者不必逐一點導覽試探。

## 4. 數字對齊

整理時發現幾處寫死的數字：首頁地圖寫「44 條」『1031 題』「34 條」『19 點』。
其中 44 與 1031 有資料源（`LS.law.條數`、`LS.meta.stats.items`），已在通則頁動態取；首頁地圖這幾句仍是字面值——
**已知不一致風險**，若條數再變，需同步改 `MAP` 陣列。已記在這裡，不假裝沒有。
