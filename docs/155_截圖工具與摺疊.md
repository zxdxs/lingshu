# 155 截圖工具修好，注家頁摺疊

## 一、先說故障

上一輪我說『截圖沒更新成功，得到 11 KB 近空白圖』。追下去才發現真正的原因不是滾動腳本，
而是**本機的 http 服務已經掛了**：Chrome 連不上 `127.0.0.1:8080`，拍到的自然是錯誤頁／空白頁。
更糟的是，我拿不到視覺回饋（視覺 API 一直 429），只能看檔案大小猜——於是同一張 459 KB 的舊圖
被我當成「新圖」交出去兩次（md5 完全相同）。

這是流程問題，不是運氣問題：**沒有驗收手段的產出，不能算完成。**

## 二、修法：`scripts/shot.py`

一支小工具，三段式自我驗收：

1. **量高**：注入 `document.title = 'H' + scrollHeight`，用 `--dump-dom` 讀回來；
2. **截圖**：用該高度當視窗尺寸再截（預設上限 20,000px，超過會明講只截上面）；
3. **驗圖**：用 PIL 算『非底色像素比例』與『有內容的行數』，太低就 `✗` 並回非零。

一次實跑：

```
✓ export/reader_zhujia.png：1280×9399px、1891 KB、非底色 40.1%、有內容的行 7513
```

同時修掉一個前提：截圖／冒煙前先確認服務回 200（`curl -o /dev/null -w '%{http_code}'`）。
這一輪把服務重新起在背景（`cd reader && python3 -m http.server 8080 --bind 127.0.0.1`）。

## 四、順手：注家頁從 65,043px 摺到 9,399px

量高才發現注家頁有 **65,043px**（三家的注全展開）。讀者要滾很久才到第三家，這是設計問題。

改成 `<details>` 摺疊（零 JS），兩類處理：

- 索引型長表預設收合：八十一篇各取一條（81 條）、逐篇注文分布（81 列）、三家覆蓋（58 條）。
- 對讀型清單也收合但標明條數：類經注（50 條）、靈樞識（42 條）；集註的通則對讀（20 條）保持展開。

摺疊後量到 **9,399px**（刪掉 85%），內容一條沒少，只是折起來。
