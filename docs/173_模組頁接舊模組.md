# 173 模組頁：81 篇全上，舊模組也接進來

## 上一輪只接了 D 型

`#/module` 原本只列 D 型 32 篇，頁面上明說『舊的 49 篇主題型模組結構各異、未收』。
這一輪把舊的也接進來——不是改寫它們，而是**照原樣呈現**。

## 做法：一個通用渲染器

舊模組（36 個檔案、49 篇）的結構是歷史累積：有的鍵是「九刺」「十二節」這種表，有的是『學習目標』
這種字串陣列，有的是「五態」這種物件陣列。與其逐一改寫（會改到已驗過的內容），不如在頁面端做通用渲染：

- 字串／數字 → 一段文字
- 物件陣列 → 自動取聯集欄位做表格（最多 80 列）
- 字串陣列 → 清單（最多 60 項）
- 物件 → 逐鍵加小標題，遞迴（深度上限 3）

D 型仍用專屬版式（分層表＋誤讀＋相連通則）；主題型以『主題型｜模組名』標籤開頭，接通用渲染。

## 結果

| 項 | 數 |
|---|---|
| D 型模組 | 32 篇 |
| 主題型模組 | 51 組（檔案 36 個） |
| 兩者聯集覆蓋 | **81／81 篇** |
| 頁面節點 | 1,375（全部收合） |
| data.js | 769 → **841 KB** |

新增防線 `模組頁覆蓋篇 = 81`：從 `data/模組_*.json` 直接算 出處 篇序的聯集，數字一掉就知道有篇漏了。

## 代價與取捨

一、通用渲染不保證好看：不同模組的鍵名不一致（『九針所宜』vs「九鍼」），表格欄位由程式自動取聯集，可能出現空欄。
二、字串截斷（表格 80 列、清單 60 項）是為了不讓單一模組撐爆頁面。
三、`data.js` 增 72 KB：每次開站都會載入（離線站，可接受；若日後嫌大，可改成按需載入另一個 JS）。

## 現狀

81 篇的模組現在都能在站上讀到。檢查：`check_all` 54 項差異 0、`模組頁覆蓋篇 81`；
`check_reader` 37 項、`smoke_browser` 31 路由＋3 情境全過；截圖 1280×5,275px。

## 帳上仍掛

- Anki GUI 實機（唯一擋發布的一項，需要人按一次）。
- 主題型模組的鍵名可以逐步統一（「九針」與「九鍼」、「篇」與「條目」），但那是內容整理，不是顯示需要。
