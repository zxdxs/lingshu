# 179 交付清單：誰拿什麼、怎麼開、怎麼引

發布前的門檻（`發布待決 = 0`）過了，剩下的不是內容，是**交接**：一包 568 個檔案丟給人，
對方不知道從哪裡開始。這一輪做一份對外的交付清單。

## 清單放哪

`export/交付清單.md`——放在 `export/` 是因為那本來就是『對外檔案』的目錄，
打包時會一起進 zip；收件人解壓後在 `export/` 就看得到。

## 清單的結構

1. **一句話＋版本／授權／聯絡**：先讓人知道這是什麼、能不能用。
2. **三種收件人**：
   - 讀者（只想讀與練）：`reader/index.html`、`.apkg`、兩份 CSV、截圖；
   - 審閱者（要看取捨與版面）：大樣稿、文件索引、發布清單、能力邊界、CHANGELOG；
   - 研究者／接棒者（要回查與重建）：底本、vendor 來源、data、scripts、重建指令。
3. **怎麼引註**：站名＋版本；篇用『篇序＋篇名』；**句 ID 是本站加的、不穩定**，引用要附原文；
   注家要標『轉引／節錄』。
4. **校驗**：`dist/manifest-v1.0.0.json` 有每個檔案的 sha256 與 `zip_sha256`，並給一行核對指令。
5. **已知限制摘要**：五條，指向 `data/能力邊界.csv`。
6. **不要做什麼**：不得據以施治；不得移除安全提醒與能力邊界；不得改原文層。

## 這輪刻意不做的事

- 沒有另做『讀者手冊』PDF：大樣稿已經是可列印的版面樣本，再拆一份會重複維護。
- 沒有把 `vendor/` 的原始錄文放進 zip（只放 `vendor/README.md` 記來源）：體積大、且屬他站錄文，
  要回查時按 README 的網址重取即可。
- 沒有寫『安裝 Anki』教學：Anki 自己的說明比我們寫得準，清單只寫『哪個檔、哪一版測過』。

## 驗收

- `交付清單.md` 內提到的檔案都存在（`reader/index.html`、`export/靈樞_填空.apkg`、
  `export/題庫_全.csv`、`export/句索引.csv`、`export/大樣稿.html`、`data/能力邊界.csv`、`docs/00_索引.md`）。
- 檔數與大小與最新打包一致（570 檔、28.5 MB）——打包後若數字變，清單要一起改。
- `check_all` 差異 0；`check_reader`、`smoke_browser` 全過。

## 局限

一、清單假設收件人會解壓並用瀏覽器開檔；若對方只想要 PDF，需要另外轉（未做）。
二、引註格式是本站自訂的慣例，不是任何期刊格式。
三、zip 內的 sha256 由 manifest 提供，但 manifest 本身不在 zip 內（在 `dist/`）。
