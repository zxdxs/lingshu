# 180 做成網站：site/ 與 GitHub Pages

## 目標

把閱讀器變成一個**可以直接開的網址**（GitHub Pages），不改內容：`site/` 是 `reader/` 的複製品，
只是加上 `.nojekyll`、授權與交付清單。

## 產物

- `scripts/build_site.py`：重建 `site/`（index.html、assets/、LICENSE.txt、交付清單.md、404.html、.nojekyll）
- `site/`：8 個檔案、1.8 MB（`assets/data.js` 佔大部分）
- `scripts/deploy_pages.sh`：把 `site/` 推到 `gh-pages` 分支

## 為什麼是 gh-pages 分支

GitHub Pages 只能從『分支的 / 或 /docs』發布。本站的 `docs/` 是說明文件（markdown），
不能當站台；所以用另一個分支 `gh-pages` 放 `site/` 的內容。主分支保持原樣（底本、data、scripts 都在）。

## 部署指令

```
scripts/deploy_pages.sh git@github.com:<user>/<repo>.git
```

腳本會：重建 site → 用暫存 worktree 建／更新 gh-pages → push → 收掉 worktree。
之後到 repo 的 Settings → Pages：Source 選「Deploy from a branch」，Branch 選 `gh-pages` / `(root)`。

網址形如 `https://<user>.github.io/<repo>/`。本站用 hash 路由，放在子路徑下不需要改任何設定。

## 為什麼不直接放 main

一、`docs/` 已被說明文件佔用；二、主分支的內容（vendor、scripts）不該整包上站；
三、Pages 每次 push 都重建，分支分開比較不會誤觸。

## 本地預覽

```
python3 scripts/build_site.py
cd site && python3 -m http.server 8081 --bind 127.0.0.1
```

已驗證：`/index.html`、`/assets/data.js` 皆 200，Chrome headless 載入後可看到首頁與導覽。

## 限制

一、GitHub Pages 是靜態服務，沒有後端；本站本來就是純靜態，沒有影響。
二、Pages 對單檔有 100 MB 上限、站台 1 GB 軟上限；本站 1.8 MB，離上限很遠。
三、`site/` 是產物：不要手改，改 `reader/` 再重建。
