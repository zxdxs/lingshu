# 185 重整資訊架構，加上誦讀

## 一、為什麼『太散』

你的感覺有根據，而且量得出來：

- 導覽列 **22 個入口**，全部平列。首頁除了標題與統計，還有五個主題卡、全站地圖、通則卡、素問卡、訓練表、驗收四層表、不做什麼——**七個區塊**，每塊都在搶注意力。
- 入口之間沒有『先看哪個』的順序：主題、通則、通讀、路徑、模組、題庫、注家、校勘、治理……對第一次來的人都是同一層。
- 有些數字還是舊的（首頁地圖寫『1031 題』『19 點』『四組模板』）。

## 二、改了什麼

### 1. 導覽：22 個平列 → 6 個入口

| 入口 | 收進去 |
|---|---|
| **首頁** | — |
| **讀 ▾** | 通讀 81 篇、誦讀、注家、十二經、病候、變體、九宫八風 |
| **學 ▾** | 學習路徑、五個主題、通則 65 條、模組 |
| **練 ▾** | 題庫、概念卡、九鍼 |
| **校 ▾** | 校勘、異同、治理與預算、限制 |
| **更多 ▾** | 搜尋、方法、我的、關於、指正與聯絡 |

用原生 `<details>`，無 JS、可鍵盤操作、離線可用；分組內有當前頁時，上層會亮。所有 24 個視圖仍可達。

### 2. 首頁：七個區塊 → 四扇門

- 開頭四顆按鈕：**讀原文／誦讀／練題／依路徑**。
- **四扇門**（讀、學、練、校）各一張卡，每卡 2–4 個連結，一行的說明。
- 統計（篇、字、題、引文段）。
- 『全部頁面』依同一套分組列出（給需要找特定頁的人）。
- 最後一段只留兩句邊界，其餘連到限制／治理／授權／回報。

原本的五主題卡、通則卡、素問卡、訓練表、驗收四層表都收掉了——它們的內容在各自頁面，不該在首頁重複一次。

### 3. 新增『誦讀』`#/recite`

- 選篇（81 篇下拉）→ 逐句朗讀，讀到哪句亮哪句，自動捲到可見處。
- 控制：播放／暫停、上一句、下一句、重讀、速度（0.7–1.2×）、循環本篇。
- 句 ID 顯示在每句左側，方便對紙本。
- 讀原文頁每篇多一顆『誦讀本篇』。
- 用**系統語音**（Web Speech API），不預錄音檔：可離線、體積零、速度可調。
- 語音是異步載入的：`getVoices()` 一開始常是空的，所以接 `voiceschanged` 再更新；偏好 zh-TW → zh-HK → 其他中文。
- 換頁時自動 `speechSynthesis.cancel()`，不會背景唸。

## 三、照實說的限制

一、**不是人聲**：系統語音的發音、斷句不是定本；多音字、罕字（音釋層的反切）沒有唸進來。頁面上寫明了。
二、系統沒裝中文語音時，頁面會直接說『系統還沒有回報中文語音』，不會假裝能唸。
三、我這邊的測試環境是 headless Chrome，**沒有語音引擎**，所以我只驗到：控制項與 85 句都渲染、語音狀態文字正確、換頁會取消。**聲音本身我沒聽過**。
四、這次只做『原文逐句』，沒有做『通則朗讀』『注家朗讀』。
