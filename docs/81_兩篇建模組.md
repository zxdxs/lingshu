續 `docs/80`。稽核的結論是『沒有模組，就生不出內容題』，這一篇把模組補上。
**引號規矩同前**：「」只給《靈樞》原文，經機器驗證；『』給其他典籍、注家與我自撰的詞。

---

## 一、模組是什麼

模組是產線的中間層：把一篇的知識點寫成結構化資料，生成器再從資料出題。

現有 33 個模組（`data/模組_*.json`），形狀大致是『條目陣列＋校記』。以 `模組_治則.json` 為例：

| 欄位 | 作用 |
|---|---|
| `條`／`條件` | 知識點名稱 |
| `原文` | 該條的底本原文（生成題面的唯一來源） |
| `說明` | 給題目附註，不進題面 |
| `校記` | 已知爭議，出題時避開或加註 |

〔歸〕這個結構的關鍵是 **`原文` 欄必須逐字**。`docs/80` 查出 37.6% 的引文不是逐字，根因就是舊模組用『條件＋者』拼接字串，而沒有存原文。

## 三、出題策略

兩個模組用兩種題型，因為內容性質不同。

**血絡論 → 選擇題（8 題）**

八問八答天然成組：問句當題面，八個答案互為干擾項。

題面：『《靈樞·血絡論》：「刺血絡而仆者，何也？」』，四個選項是——

1. 「脉氣盛而血虛者，刺之則脫氣，脫氣則仆」
2. 「血氣俱盛而陰氣多者，其血滑，刺之則射」
3. 「陽氣畜積，久留而不寫者，其血黒以濁，故不能射」
4. 「新飲而液渗于絡，而未合和于血也，故血出而汁別焉」

干擾項全部來自同一篇的其他答案，不是編造——這是本專案一貫的規矩。而且四個選項都是『氣血狀態＋推論』，形式上對等，不會憑長度猜中。

**陰陽清濁 → 填空題（10 題）**

每條挖一處，答案就是被挖掉的字：

例：「受穀者濁，受氣者清」，挖去「濁」——題面把「濁」換成空格。

例：「清濁相干，命曰亂氣」，挖去「亂氣」——題面作「清濁相干，命曰____」。

題面直接取模組的 `原文`，`replace(答案, '____', 1)`——**生成器沒有機會改動任何一個字**。

## 五、新產生的問題（誠實列出）

1. **F5 單字答案從 78 增到 88（+10）。** 新填空多數答案只有一個字（濁、陽、肺、海、清、濇、鍼、堅）。單字答案的「正解面」很寬——寫「清」和寫「清氣」哪個算對？目前靠 `exact` 評分，等於默認只收一個字面。這是可改的：要嘛加同義答案表，要嘛把空挖在兩字以上的詞上。
2. **血絡論的答案偏長（18–23 字）。** 用來當選擇題選項尚可（四項長度相近），但若轉成填空就不能用——生成器對 fill_blank 有 F1 長答案限制，這裡剛好沒踩到，是因為只出了 mcq。
3. **八題共用一組答案池。** 同一題的干擾項可能是另一題的正解，這在設計上是優點（逼學員分辨），但若學員連續作答，會有記憶干擾。未實測，僅記錄。
4. **`模組_血絡.json` 的校記列了三條爭議**（血絡是狀態還是結構、失數而反的兩讀、劑量在別篇），出題時都避開了這三處。避開也是取捨：這篇最難的地方，正好沒題。

## 七、一句話

模組不是『整理好的筆記』，是『唯一允許生成器動手的原料』。把原料從拼接字串換成逐字原文之後，題目的引文就自動可信了——**這不是靠校對，是靠不給它改字的機會。**
