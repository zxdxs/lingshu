# 86 Anki 填空卡：把「對答案」做進卡片裡

續 `docs/85`。有了評分器，還缺最後一段：學員手上真的有一副可以作答的卡片。
**引號規矩同前**：「」只給《靈樞》原文，經機器驗證；『』給其他典籍、注家與我自撰的詞。

---

## 一、原本的卡片不能作答

`export/anki_靈樞.csv` 是『正面題目、背面答案』的基本卡：看到題目，心裡想一個答案，翻面核對。

這沒有錯，但有一個缺口：**沒有人檢查你寫的對不對**。你以為自己會，其實只是看懂了答案。

〔歸〕回想式學習（active recall）的要點是『先產出、再核對』。翻面卡只做到後半。

---

## 二、為什麼不用 Anki 內建的 `{{type:答案}}`

Anki 有『打字輸入』功能，但它只做很淺的比對：忽略大小寫、可選忽略重音。**它不認異體字。**

「隂谷」會被判錯，「脈」與「脉」算兩個詞。而這正是 `docs/83`、`docs/85` 花了兩輪處理的問題。

所以內建功能不夠用，得自己做。

---

## 三、做法：自訂卡片模板 + 同一張異體表

```
export/anki模板/front.html   正面：題面 + 輸入框 + 即時判定
export/anki模板/back.html    背面：答案、可接受寫法、說明、出處
export/anki模板/style.css
export/異體映射.json          29 組異體（與 scripts/grade.py 共用）
        ↓ scripts/build_anki_deck.py
export/靈樞_填空.apkg         600 張填空卡
```

正面長這樣：

```
《靈樞·本輸》：『肺出於____，為井。』
[___________] [對答案]
```

輸入後按 Enter，當場顯示「正確」或「再想想」。判定邏輯三行，和 `grade.py` 完全一樣：

1. NFKC 正規化（全形數字）
2. 去空白與標點
3. 查異體表替字

**重點是『同一張表』**：JS 版與 Python 版共用 `export/異體映射.json`，所以不會出現『程式說對、卡片說錯』。

---

## 四、驗證（三層）

### （1）檔案結構

解開 `.apkg`（就是一個 zip，內含 sqlite）：

```
notes 600　cards 600
model 靈樞填空（可對答案）
fields ['題面','答案','可接受','說明','出處']
qfmt 含 VAR: True
```

### （2）JS 正規化單元測試

用 node 直接抽出模板裡的 `normalize()` 跑 9 個案例：

| 測項 | 結果 |
|---|---|
| 隂谷＝陰谷 | ✅ |
| 陰谷。＝陰谷 | ✅ |
| ３斗５升＝3斗5升 | ✅ |
| 為＝爲 | ✅ |
| 清氣≠清、三斗五鬥≠三斗五升 | ✅（正確判錯） |

**9 例 0 失敗。**

### （3）跨語言一致性

拿 104 個真實樣本（正解、異體、同篇他題的錯答），同時用 JS 與 `grade.py` 判：

```
跨語言比對 104 例，分歧 0
```

這一層最要緊：兩套實作若各判各的，學員會遇到『同樣的答案有時對有時錯』。

---

## 五、怎麼用

1. 開 Anki → 檔案 → 匯入 → 選 `export/靈樞_填空.apkg`
2. 牌組『靈樞·自學』出現 600 張填空卡
3. 正面輸入答案，Enter 即時判定；翻面看完整答案、可接受寫法與出處

**不需要外掛、不需要網路。**

---

## 六、四項限制（誠實列出）

1. **JS 只做自檢，不影響排程。** 你在正面答對與否，Anki 的間隔演算法不知道——它仍以你翻面後按的『良好／再次』為準。**這不是自動評分，是即時回饋。**
2. **只做了填空題 600 張。** 選擇題 299 張、辨誤題 19 張仍在 CSV 裡，沒有做成卡片（它們不需要打字）。
3. **沒有在真機上跑過。** 我用 node 測了判定邏輯，用 sqlite 驗了檔案結構，但**沒有在 Anki 桌面版或 AnkiDroid 實際匯入、實際按鍵**。模板內的 DOM 依賴（`getElementById`）在 Anki 的 webview 裡應該可用，但這是推論，不是實測。
4. **簡體仍不接受。** 與 `docs/85` 同一個限制，沒有改變。

## 七、工程細節：genanki 裝在 workspace

`pip install genanki` 因為權限被擋（venv 在 workspace 外）。改用：

```
pip install --target ./vendor/pylib genanki
```

建卡時 `sys.path` 先指向 `vendor/pylib`。**這不是乾淨的做法**——正常應該用 venv 或 requirements。但在『不能寫入系統目錄』的前提下，這是能跑的最小方案，且已寫進腳本註解。

---

## 八、一句話

一張卡的價值不在它印了什麼，在它能不能讓你先寫、再核對。這一輪把「核對」從人的眼睛移到卡片的 JS，代價是它只回饋、不記錄——**知道這條界線在哪，比多做 300 張卡重要。**
