# 89 繁簡對照：讓簡體作答也判對

續 `docs/85`。那一輪的第三項限制是『簡體只覆蓋 22 條』；這一輪把它補完。
**引號規矩同前**：「」只給《靈樞》原文，經機器驗證；『』給其他典籍、注家與我自撰的詞。

---

## 一、上一輪為什麼停手

`docs/83` 拒絕了 OpenCC，理由是：

> 自動轉換會把「乾」轉成「干」這種在醫書裡會出事的字。

這個理由**對一半**。

- 如果拿它去**改寫原文**，風險很大：乾（乾燥）與干（干犯）在醫書裡是兩個意思。
- 但如果只是拿它去**收斂判分時的輸入**，風險很小：學員打「干」而答案是「乾」，我們希望他過。

〔歸〕同一張表，用在顯示上是竄改，用在比對上是寬容。**差別不在表，在用途。**

所以這一輪的定位很明確：**只用來判分，不用來改字。**

---

## 二、做法：離線產生、存成表、入庫可查

```
OpenCC（離線跑一次）
   ↓ 對『底本 + 答案』出現過的 1,906 個字逐字轉換
data/繁簡映射.csv     556 對（只收有差異的字）
   ↓
scripts/grade.py      normalize() 多一步：VAR 收斂 → 繁簡收斂
scripts/generate_items.py  每題多算一個簡體寫法，放進可接受答案
```

為什麼是「逐字」而不是「整串」：整串轉換會做詞組判斷（例如「著」在不同詞裡轉成「着」或「著」），逐字則完全可預測。**判分要的是可預測，不是最聰明。**

為什麼存成 CSV：這張表會用在工作站、Anki 模板與未來的評分器；存成純資料，三邊才不會各算各的。

---

## 三、風險字：只有三個

在 556 對裡，真正會『合併不同字』的只有：

| 繁 | 簡 | 說明 |
|---|---|---|
| 乾 | 干 | 乾燥／干犯 |
| 幹 | 干 | 幹事／干犯 |
| 髮 | 发 | 頭髮／發生 |

這三個在**判分**上無害（打字的人用哪個都算對），但在**顯示**上會失真。所以它們只出現在映射表裡，不會去改任何原文或答案欄位。

〔歸〕我把「合併」當成特性，不是 bug：學員不需要知道「乾」的簡體是哪個字，他只需要知道自己的答案對不對。

---

## 四、驗證：先確認沒有把不同答案併成一題

寬容的最大風險是『本來該錯的變成對的』。所以先檢查：**有沒有兩個不同的答案，經過正規化後變成同一個？**

```
原始答案 498 個｜碰撞組 0
```

沒有。繁簡收斂沒有把任何兩個答案混在一起。

再跑評分器自我測試：

```
填空題 594｜正解通過 594｜異體樣本 478｜簡體樣本 6｜負樣本 13000（誤收 0）｜失敗 0
```

| 測項 | 樣本 | 結果 |
|---|---:|---:|
| 正解 | 594 | 全過 |
| 異體（含簡體）寫法 | 478 | 全過 |
| 指定簡體案例（阴谷／鱼际／肾／经渠／气／乱气） | 6 | 全過 |
| **同篇別題的答案** | 13,000 | **誤收 0** |

負樣本仍是 0 誤收——**放寬的是字形，不是答案。**

## 五、出題端的變化

可接受答案從 130 題增加到 **336 題**：

```
魚際 → 鱼际
太淵 → 大淵、太渊
經渠 → 经渠
```

（「大淵」是底本寫法，「太渊」是簡體，兩者並列。）

Anki 卡片同步重建：594 張，正面輸入簡體也會判對——因為卡片 JS 用的是同一張表。

---

## 六、剩下的限制

1. **只涵蓋底本與答案出現過的字。** 學員若打出一個罕用異體（例如「㿉」的某種寫法），仍可能判錯。這不是表不夠大，是異體無窮。
2. **不做錯字容錯。** 「三斗五升」打成『三斗五鬥』仍然錯。刻意的。
3. **顯示層不動。** 原文、答案、文件都用繁體；簡體只活在比對裡。
4. **Anki 端仍未實機測試**（`docs/86` 的限制沒有改變）。

---

## 七、一句話

上一輪我把 OpenCC 當成『會弄壞原文的工具』而拒絕；這一輪發現它只是站錯位置——**放在判分器裡，它就是寬容；放在編輯器裡，它才是竄改。**
