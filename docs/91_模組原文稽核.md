# 91 模組原文的機器稽核：264 條，全部落地

續 `docs/90`。那一輪末尾留了一句：『模組的『原文』欄沒有機器校驗』。這一輪把它補上。
**引號規矩同前**：「」只給《靈樞》原文，經機器驗證；『』給其他典籍、注家與我自撰的詞。

---

## 一、為什麼要單獨查一次

題庫的引文已經逐段驗過（`docs/88`：645 段、0 不符）。但題面是**從模組生成的**——模組的「原文」欄若本身有錯，題面只是忠實地重複那個錯。

`docs/90` 抓到的例子很典型：`模組_歲露論` 的「原文」寫著『衛氣一日一夜常大會於風府』，整整齊齊，卻不在靈樞——它出自素問·瘧論。

〔歸〕**驗題面只證明『題面等於模組』，不證明『模組等於原文』。** 兩層要分開查。

---

## 二、查法：不信任模組結構，只信任底本

模組有 33 個，結構各不相同（有的 `出處` 是物件，有的是陣列；有的列在條目上，有的只在檔案層）。硬猜『這條屬於哪篇』很容易猜錯——我先前的草稿就猜錯過一次，把水脹的條目記到五亂名下。

所以換一個判法：

| 情況 | 判定 |
|---|---|
| 條目有明確篇名（自身或最近上層，或模組出處只有一篇） | 必須見於該篇，否則記「錯置」 |
| 沒有篇名 | 必須見於 81 篇之一，並記下**實際**落在哪篇 |
| 哪裡都找不到 | 記『不在底本』 |

第二、三種不需要知道『應該屬於哪篇』，所以不會被模組的錯誤標記帶偏。

工具：`scripts/audit_module_text.py`，輸出 `data/模組原文稽核.csv`。

## 三、結果

```
模組原文條目 264｜OK 213｜OK（篇未標）51｜錯置 0｜不在底本 0
```

| 狀態 | 條數 | 說明 |
|---|---:|---|
| OK | 213 | 有篇名，且逐字見於該篇 |
| OK（篇未標） | 51 | 見於底本，但模組沒標篇名 |

| 不在底本 | **0** | 任何篇都沒有 |

**264 條全部落地。** 上一輪抓到的歲露論那條已經在 `docs/90` 剔除，所以這次是 0。

---

## 四、過程中修的唯一一條

初次跑出來是 1 條『不在底本』：`模組_摘句` 引〈行鍼〉「重陽之人，熇熇高高，言語善疾……」。

回底本比對，只差一個字：底本作「熇熇**髙**髙」，模組作「熇熇**高**高」——`高`（U+9AD8）與 `髙`（U+9AD9）是異體。

補進異體字表即可。**這一條從頭到尾不是內容錯，是字形表漏收。**

〔歸〕這也是為什麼清理要分兩層：內容錯（歲露論）與字形錯（髙／高）在報表上都長成「找不到」，但處置完全不同。

---

## 五、那 51 條「篇未標」

集中在 `模組_度量`（41 條，骨度／腸胃／五十營等度量表）、`模組_概念2`（7 條）、`模組_B2`（3 條）。

- 它們**都只有一個出處**（唯一命中，沒有跨篇歧義）；
- 只是模組把篇名放在檔案層的陣列裡，條目本身沒帶。

〔歸〕這不是錯誤，是可追溯性的折扣：讀者拿到一條度量數據，得自己往上翻才知道它出自哪篇。要補的話，是給這 51 條加 `篇名` 欄——資料整理工作，不影響正確性，本輪沒做。

## 八、一句話

題面乾淨不代表模組乾淨。**驗一層只能證明那一層；要證明整條鏈，得每一層都驗一次。** 264 條全部落地，靠的不是更嚴的標準，是把『這條屬於哪篇』換成『這條在哪裡』——問對問題，答案就自己出來了。
