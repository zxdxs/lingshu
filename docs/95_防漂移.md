# 95 防漂移：讓改動留下痕跡

續 `docs/93` 的第二優先。那一輪盤點出六條『便宜且會持續惡化』的缺口，這一輪一起補。
**引號規矩同前**：「」只給《靈樞》原文，經機器驗證；『』給其他典籍、注家與我自撰的詞。

---

## 一、先講最根本的一條：沒有版本控制

這個專案有 95 份文件、900 道題、81 篇底本，**卻沒有 `.git`**。

也就是說：任何一次改動都不可回溯，任何一次誤刪都無法挽回，任何一次『上週那個數字是多少』都只能靠記憶。

補上：

```
git init
.gitignore   —— vendor/pylib（可重裝依賴）、.dsh-vision-toolkit、__pycache__、原始 PDF
首次提交    —— 81 篇底本、900 題、95 份文件
```

〔歸〕這件事花不到十分鐘，但它改變了後面所有工作的性質：**從『改完就沒有回頭路』變成『改壞了可以比對』。**

---

## 二、回歸檢查：14 個指標，一個基準檔

`scripts/check_all.py` 把散在四支稽核裡的結果收斂成一份：

```json
{
 "題數": 900, "填空": 583, "選擇": 298, "辨誤": 19,
 "題面引文不符": 0, "答案原文": 544, "答案整理語": 15, "答案推算": 24,
 "模組原文條目": 264, "模組原文不符": 0,
 "重複題面": 0, "篇名不一致": 0,
 "文件引文待核": 0, "文件數": 95
}
```

用法：

```
python3 scripts/check_all.py           # 與 data/基準.json 比對，有差異就非零退出
python3 scripts/check_all.py --write   # 確認改動後更新基準
```

〔歸〕關鍵設計是**基準檔要人工更新**。若讓它自動跟著現況走，它就只是一份說明；要人看一眼再按下去，它才是閘門。

## 三、數字不再手寫

README 的四個數字長期是手寫的，於是漂移：

| 項目 | README 曾寫 | 實際 |
|---|---|---|
| 模組 | 47 篇 | 49 篇 |
| 能力邊界 | 29 條 | 34 條 |

現在由 `scripts/sync_docs.py` 從資料重算並改寫 README：

```
README 同步：題數 900、模組 49 篇、能力邊界 34 條、文件 95 份
```

同一支腳本順便產生 `docs/00_索引.md`——**95 份文件的自動索引**，標題取自各檔第一行 `#`。

〔歸〕以前 README 只列了 60 餘份，剩下 16 份『存在但找不到』。索引自動產生之後，這個問題不會再回來。

---

## 四、篇名不一致：三組，歸零

題目來源寫「脈度」『九宮八風』『壽夭剛柔』，底本作「脉度」『九宫八風』『夀夭剛柔』。

13 道題受影響。**任何按篇名 join 的程式都會漏掉它們。**

修法：生成器末端統一用底本的規範篇名（依篇序查表），不再信任來源字串。

```
篇名不一致：13 → 0
```

---

## 五、重複題：11 組，歸零

同樣的題面出現兩次，佔了複習時間卻沒有增加資訊。

生成器末端加去重（保留第一筆，記數）：

```
生成 900 題（去重 11）
```

題數 911 → **900**。

〔歸〕這一步會改變題數，所以必須**先有基準檔再改**——否則沒人知道 911 變成 900 是去重還是丟題。

| 檢查 | 工具 | 目前 |
|---|---|---|
| 題面逐字 | `audit_item_quotes.py` | 0 不符 |
| 答案類型 | `audit_item_answers.py` | 544／15／24 |
| 模組原文 | `audit_module_text.py` | 264 條全 OK |
| 模組說明引文 | `audit_module_prose.py` | 0 不符 |
| 文件引文 | `check_quotes.py` | 0 待核 |
| 十四項指標 | `check_all.py` | 差異 0 |
| README／索引 | `sync_docs.py` | 已同步 |

**六支工具共用同一張異體字表**——表漏一個字，六支會一起報錯，這反而是好事：錯誤會集中出現，不會被某一支默默吞掉。

---

## 七、這套閘門抓不到什麼

1. **語意錯誤**：引文逐字、答案類型正確，但題意仍可能問錯。機器只驗『字對不對』。
2. **內容取捨**：16 篇只有 1–2 題、53% 是記憶題，這些基準檔會『如實記錄』，不會報警。
3. **註家配對品質**：19 條待專家核，基準檔只記數字。
4. **白話翻譯對不對**：`audit_module_prose.py` 只查有沒有誤引。

〔歸〕這套東西的定位是**防退化**，不是**保品質**。它能保證『昨天對的今天還對』，不能保證『昨天就對』。

---

## 八、一句話

漂移不是因為有人做錯，是因為**沒有人會發現**。加了 git、基準檔與自動同步之後，數字錯了會有人叫、改動了會留下痕跡、文件不會再『存在但找不到』——**這不是让內容變好，是讓內容變壞時看得見。**
