續 `docs/96`。那一輪留下兩件：① 十六篇再各補 3–4 題 ② 做案例題樣板。這一輪一起做。
**引號規矩同前**：「」只給《靈樞》原文，經機器驗證；『』給其他典籍、注家與我自撰的詞。

## 一、十六篇補到六題

`docs/96` 給每篇兩題，這一輪再加四題，共 **96 條**（16 篇 × 6）。

做法不變：每句都是該篇樞紐句，只挖一處，句與答案都先過機器核對才寫進檔案。

```
模組_薄篇.json：96 條
16 篇：各 7 題（1 題摘要 + 6 題填空）
```

驗證：新增 64 條引文，0 不符。

## 二、案例題樣板：先解決『答案洩漏』

第一版做出來是這樣：

```
《靈樞·厥病》：「厥心痛，腹脹胷滿，心尤痛甚，胃心痛也」……「取之大都、大白」。屬哪一型？
```

**題面自己就把答案寫出來了**——「胃心痛也」與「取之大都、大白」都在引文裡。這是循環提示（`F6`），比沒有題更糟。

改成：**題面只放證候片段，把證型名與治法切掉**。

```
《靈樞·厥病》：「厥心痛，腹脹胷滿，心尤痛甚」。依〈厥病〉，此屬五心痛之哪一型？當取何穴？
答：胃心痛；取大都、大白
```

〔歸〕案例題的關鍵不是『編一個病人』，是**決定哪一段原文可以給、哪一段必須藏**。給多了就是循環提示，給少了就猜不出來。

---

## 四、為什麼標『待專家核』

這六題的每一個字都能回到底本，但**『這樣的題是否真的在考辨證』**，我判斷不了。

真正的案例題應該有：病情演變、脈證合參、鑑別診斷、誤治後的變化。這六題只是『把原文的診斷句藏起來』——它是樣板，不是成品。

〔歸〕`docs/42` 把『臨床推理』列為 AI 無能為力之一。這一輪做的是**格式與驗證管線**：只要有人寫得出案例，就能直接進這條管線（機器會檢查引文、答案洩漏、干擾項來源）。
